Command reference

Current v4 API surface

This is the manual-grade reference for the shipped Tuba v4 Python API. Every signature below is copied from the source, and every unit is SI: meters, pascal, Celsius, newton, kilograms, and derived SI combinations. Sections run in call order — author a model, build pipe with the cursor DSL, describe operating states, export and solve a Code_Aster study, then check compliance, optimize supports, take off quantities, serialize, and autoroute. For section geometry, coordinate frames, and validation rules, see Modeling.

Operating-state commands

Operating states reuse define_load_case and define_operation from the model commands above. A load case is uniform; an operation may additionally carry non-uniform per-element fields added with op.add_field(...). Both map their pressure argument to the record's internal_pressure.

Uniform operation

hot = model.define_operation(
    "Hot",
    gravity=True,
    pressure=1.6e6,
    temperature=180.0,
    ref_temperature=20.0,
)

Route/station field

hot.add_field(
    "temperature",
    140.0,
    route_id="P-100",
    station_start=0.0,
    station_end=1.5,
)

Supported operation-field quantities are pressure, temperature, and wind. Linear route/station temperature fields are exported as per-element midpoint assignments. Non-uniform pressure, non-uniform wind, and piecewise profiles fail validation before export.

Tabular reports (line list, sections, reactions)

The same scene also drives the sign-and-archive deliverables a piping engineer expects — a line list, a cross-section schedule, a load-case summary, and per-load-case stress, reaction, and displacement tables. Each report is a pure function (scene → list[dict]) in tuba.visualization.reports, so it feeds a CSV, an HTML table, or a DataFrame equally well.

build_reports(scene: VisualizationScene) -> dict[str, list[dict]]

Return every report keyed by name: line_list, section_schedule, load_case_summary, stress, reactions, displacements. Call any one directly (e.g. line_list(scene)) for a single table.

write_report_csvs(scene: VisualizationScene, directory: str | Path) -> list[Path]

Write one CSV per non-empty report into directory and return the paths.

write_static_report calls this for you: it drops the CSVs under reports/ and renders each table into the shareable index.html alongside a download link. 

from tuba.visualization import build_visualization_scene, line_list, write_report_csvs
from tuba.visualization.static_report import write_static_report

scene = build_visualization_scene(model, solver_results=results, result_states=[state])

# One table as plain rows...
for row in line_list(scene):
    print(row["name"], row["od_m"], row["length_m"], row["mass_kg"])

# ...or the full self-contained report folder (HTML tables + CSVs + scene bundle).
report = write_static_report(scene, "reports/HOT-100", title="HOT-100 review")
print(report.index_path)

Compliance (ASME B31.3)

Objectives

Every objective subclasses BaseObjective(weight=1.0) and implements evaluate(...) -> float (a scalar penalty where 0.0 is perfect and higher is worse) and get_details(...) -> Dict[str, Any]. ObjectiveEvaluator aggregates a list of objectives.
