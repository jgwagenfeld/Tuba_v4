Interactive engineering review

One package, seven review workflows

After the mandatory Code_Aster solve and artifact import, Python writes the engineering review package. The Three.js viewer consumes that package; it does not calculate stresses, reactions, displacements, or compliance in the browser.

  1. Summary — status, provenance, governing results, and warnings.
  2. Model — nodes, line list, sections, materials, and supports.
  3. Load Cases — definitions, studies, and solve lineage.
  4. Results — Code_Aster result states, FE stress, displacements, reactions, and forces.
  5. Compliance — explicit piping-code checks when a ComplianceReport is supplied.
  6. 3D — spatial selection, overlays, issues, and display-only deformation controls.
  7. Diagnostics — package, scene, parser, and provenance diagnostics.

Use tuba.plotting with PyVista for quick-look and export. Use tuba.visualization plus the Three.js viewer for a shareable review bundle. Both display real Code_Aster-backed results; neither replaces the solve.

How the manual is organized

The site follows a documentation split used by mature technical manuals: the tutorial teaches the first complete model-to-results run, modeling and autorouting go deep on tasks, commands is the reference, and overview/developer explain design boundaries — including the one rule the whole project holds to: exported study files are a handoff, and only real Code_Aster artifacts back a stress, displacement, reaction, or compliance result (see the result boundary).
