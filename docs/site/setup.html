Setup

Run Tuba locally

The hosted page is documentation and preserved artifact review. New engineering solves need a local Python environment and a working Code_Aster runtime.

Prerequisites

RequirementDetail
Python3.10, 3.11, or 3.12 (requires-python >= 3.10).
GitTo clone the repository and run from a checkout.
Operating systemThe package is OS-independent, but the tested Code_Aster runtime path is Linux — native, or Windows through WSL Ubuntu.
Code_AsterRequired only for solving. Authoring, export, and reviewing preserved artifacts work without it.
Disk / memoryA few GB for the WSL Code_Aster install; solves are small for tutorial models but scale with mesh size.

Clone the tagged beta

git clone --branch v4.0.1 --depth 1 https://github.com/jgwagenfeld/Tuba_v4.git
cd Tuba_v4

Tuba installs from this checkout. The install extras below decide which optional features are available.

InstallAdds
python -m pip install .Core: model authoring, validation, Code_Aster study export, and routing.
.[notebook-viz]JupyterLab, ipywidgets, and the full PyVista/Trame stack for interactive notebooks.
.[course]All dependencies used by the 14 notebooks, including notebook execution, PyVista/Trame, IFC, and imported-mesh lessons.
.[ifc]IFC4 import/export through ifcopenshell.
.[code-aster-rmed]h5py for reading RMED/MED result files.

1. Create or activate the Python environment

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install ".[course]"

2. Install Code_Aster in WSL Ubuntu

pip installs Tuba, not Code_Aster. The code-aster-rmed extra adds result-file reading only. The tested Windows setup installs the Linux solver from conda-forge inside WSL2 Ubuntu. 

wsl --install -d Ubuntu
wsl --list --verbose

Restart Windows if requested, then launch Ubuntu once and create its Linux username and password before continuing. See Microsoft's WSL installation guide if the command is unavailable.

Install Miniforge inside Ubuntu from PowerShell:

@'
set -euo pipefail
cd /tmp
curl -L -o Miniforge3-Linux-x86_64.sh \
  https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh
bash Miniforge3-Linux-x86_64.sh -b -p "$HOME/miniforge3"
'@ | wsl -d Ubuntu -- bash -s

Install Code_Aster and expose run_aster:

@'
set -euo pipefail
source "$HOME/miniforge3/etc/profile.d/conda.sh"
conda create -y -n tuba-code-aster --override-channels -c conda-forge \
  python=3.12 code-aster=18.0.12
mkdir -p "$HOME/bin"
cat > "$HOME/bin/run_aster" <<'SH'
#!/usr/bin/env bash
set -euo pipefail
exec "$HOME/miniforge3/envs/tuba-code-aster/bin/run_aster" "$@"
SH
chmod +x "$HOME/bin/run_aster"
grep -qxF 'export PATH="$HOME/bin:$PATH"' "$HOME/.profile" || \
  echo 'export PATH="$HOME/bin:$PATH"' >> "$HOME/.profile"
PATH="$HOME/bin:$PATH" run_aster --version
'@ | wsl -d Ubuntu -- bash -s

Tuba v4 is validated with Code_Aster 18.0.12. Keep this pin until the real solver smoke test passes with a newer release.

Package details are available from conda-forge; runner behavior is documented in the official run_aster guide.

3. Select the runtime for Tuba

$env:TUBA_CODE_ASTER_EXEC_METHOD = "wsl"
$env:TUBA_CODE_ASTER_WSL_DISTRO = "Ubuntu"

4. Check runtime discovery

wsl --list --verbose
wsl -d Ubuntu -- bash -lc "command -v run_aster; run_aster --version"
.\.venv\Scripts\python.exe -m tuba.solver.code_aster_doctor
.\.venv\Scripts\python.exe -m tuba.solver.code_aster_doctor --check

5. Run the real solver smoke test

$env:TUBA_RUN_CODE_ASTER_INTEGRATION = "1"
.\.venv\Scripts\python.exe -m unittest tests.test_code_aster_real_smoke -v

6. Open notebooks after setup

Start with the welcome notebook. Open the postprocessor notebook only after the runtime check passes or when you are loading preserved Code_Aster artifacts. 

.\.venv\Scripts\jupyter.exe lab notebooks\00_welcome_and_setup.ipynb
.\.venv\Scripts\jupyter.exe lab notebooks\10_interactive_postprocessor.ipynb

Runtime requirement

Code_Aster is required for production stress, displacement, reaction, thermal-expansion, operating-state clash, compliance, and result visualization workflows. If --check is blocked, keep notebooks in artifact-loading mode and do not display new solver results.

Environment variables

These configure the Code_Aster runtime without editing code. Every CodeAsterSolver constructor argument has a matching variable.

VariableMeaningValues / example
TUBA_CODE_ASTER_EXEC_METHODHow Tuba launches the runner.auto (default), wsl, docker, command, python_bridge
TUBA_CODE_ASTER_WSL_DISTROWSL distribution to run inside.Ubuntu
TUBA_CODE_ASTER_DOCKER_IMAGEAdvanced fallback image for the docker method.The built-in default is mutable and not release-verified; pin a tested image digest before use.
TUBA_CODE_ASTER_RUNNER_COMMAND / TUBA_CODE_ASTER_RUNNERExplicit runner command for the command method.path to run_aster
TUBA_CODE_ASTER_PYTHONPython that hosts the in-process bridge.Use on native Linux, or only with a Python executable the host can run directly; never pass a WSL path to Windows.
TUBA_RUN_CODE_ASTER_INTEGRATIONOpt in to the real-solver smoke test (it skips otherwise).1

Troubleshooting map

Symptom Check Fix
run_aster not found wsl -d Ubuntu -- bash -lc "command -v run_aster" Expose a stable ~/bin/run_aster wrapper inside Ubuntu.
Doctor reports blocked python -m tuba.solver.code_aster_doctor --check Fix the selected runtime before running notebooks with run_solver=True.
Integration test skips $env:TUBA_RUN_CODE_ASTER_INTEGRATION Set it to 1; the test intentionally skips without an explicit opt-in.
Study exports but no results appear stdout.wsl.log, stderr.wsl.log, and study.mess Read the solver logs. Export succeeded, but Code_Aster did not finish cleanly.
