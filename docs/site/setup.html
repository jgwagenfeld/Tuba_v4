Setup

Run Tuba locally

The hosted page is documentation and preserved artifact review. New engineering solves need a local Python environment and a working Code_Aster runtime.

Prerequisites

RequirementDetail
Python3.10, 3.11, or 3.12 (requires-python >= 3.10).
GitTo clone the repository and run from a checkout.
Operating systemThe package is OS-independent, but the tested Code_Aster runtime path is Linux — native, or Windows through WSL Ubuntu.
Code_AsterRequired only for solving. Authoring, export, and reviewing preserved artifacts work without it.
Disk / memoryA few GB for the WSL Code_Aster install; solves are small for tutorial models but scale with mesh size.

Get the repository

git clone https://github.com/jgwagenfeld/Tuba_v4.git
cd Tuba_v4

Tuba installs as an editable package from this checkout. The install extras below decide which optional features are available.

InstallAdds
pip install -e .Core: model authoring, validation, export, routing, PyVista quick-look (numpy, scipy, gmsh, trimesh, pyvista).
.[notebook-viz]JupyterLab, ipywidgets, and the full PyVista/Trame stack for interactive notebooks.
.[ifc]IFC4 import/export through ifcopenshell.
.[code-aster-rmed]h5py for reading RMED/MED result files.

1. Create or activate the Python environment

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[notebook-viz]"

2. Check runtime discovery

.\.venv\Scripts\python.exe -m tuba.solver.code_aster_doctor
.\.venv\Scripts\python.exe -m tuba.solver.code_aster_doctor --check

3. Prefer WSL Ubuntu for Code_Aster on Windows

wsl --list --verbose
wsl -d Ubuntu bash -lc "command -v run_aster; run_aster --version || run_aster --help | head -20"

4. Select the runtime for Tuba

$env:TUBA_CODE_ASTER_EXEC_METHOD = "wsl"
$env:TUBA_CODE_ASTER_WSL_DISTRO = "Ubuntu"

5. Run the real solver smoke test

$env:TUBA_RUN_CODE_ASTER_INTEGRATION = "1"
.\.venv\Scripts\python.exe -m unittest tests.test_code_aster_real_smoke -v

6. Open notebooks after setup

Start with the welcome notebook. Open the postprocessor notebook only after the runtime check passes or when you are loading preserved Code_Aster artifacts. 

jupyter lab notebooks\00_welcome_and_setup.ipynb
jupyter lab notebooks\10_interactive_postprocessor.ipynb

Runtime requirement

Code_Aster is required for production stress, displacement, reaction, thermal-expansion, operating-state clash, compliance, and result visualization workflows. If --check is blocked, keep notebooks in artifact-loading mode and do not display new solver results.

Getting Code_Aster (run_aster)

Tuba does not ship Code_Aster; it drives an existing install. On Windows the tested path is a Code_Aster install inside WSL Ubuntu (from a Salome-Meca or standalone Code_Aster distribution, code-aster.org), which provides the run_aster runner. Tuba finds it by invoking your selected runtime, so the one thing that must be true is that run_aster resolves on the runtime's PATH. 

# inside WSL Ubuntu: expose a stable wrapper on PATH
mkdir -p ~/bin
ln -sf /opt/aster/bin/run_aster ~/bin/run_aster   # adjust to your install path
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc
run_aster --version
A passing code_aster_doctor --check prints the resolved execution method and the discovered run_aster path, and exits zero. That is the signal Tuba is allowed to run run_solver=True.

Environment variables

These configure the Code_Aster runtime without editing code. Every CodeAsterSolver constructor argument has a matching variable.

VariableMeaningValues / example
TUBA_CODE_ASTER_EXEC_METHODHow Tuba launches the runner.auto (default), wsl, docker, command, python_bridge
TUBA_CODE_ASTER_WSL_DISTROWSL distribution to run inside.Ubuntu
TUBA_CODE_ASTER_DOCKER_IMAGEImage for the docker method.simvia/code_aster:stable (default)
TUBA_CODE_ASTER_RUNNER_COMMAND / TUBA_CODE_ASTER_RUNNERExplicit runner command for the command method.path to run_aster
TUBA_CODE_ASTER_PYTHONPython that hosts the in-process bridge.path to the Code_Aster Python
TUBA_RUN_CODE_ASTER_INTEGRATIONOpt in to the real-solver smoke test (it skips otherwise).1

Troubleshooting map

Symptom Check Fix
run_aster not found wsl -d Ubuntu bash -lc "command -v run_aster; echo $PATH" Expose a stable ~/bin/run_aster wrapper inside Ubuntu.
Doctor reports blocked python -m tuba.solver.code_aster_doctor --check Fix the selected runtime before running notebooks with run_solver=True.
Integration test skips $env:TUBA_RUN_CODE_ASTER_INTEGRATION Set it to 1; the test intentionally skips without an explicit opt-in.
Study exports but no results appear stdout.wsl.log, stderr.wsl.log, and study.mess Read the solver logs. Export succeeded, but Code_Aster did not finish cleanly.
